# daily（1 日を回す）

置き場・ファイル名・YAML の形は `RULES.md` に従う（書く手順は `/work-rules`）。
日付・時刻は `date '+%F %H:%M %a'` で取る（推測しない）。今日の daily は `./daily/<YYYY>/<MM>/<YYYY-MM-DD>.yaml`。
スクリプトは repo のルートから `./scripts/work-render`・`./scripts/work-lint` で呼ぶ（`cd` しない）。
**`./scripts/work-render` を流す前には、必ず `./scripts/work-render --check` を先に流す。** 「手で直された」と出た md があれば、render の前に「本人が md を直したとき」の手順で YAML に戻す（render は手で直された md を上書きせずに止まる）。
**メール・チャットを送らない。予定・Google のファイルを作らない・変えない**（`RULES.md` の「取り込み」）。

## 0. 呼ばれたら、まず判断する

1. `date '+%F %H:%M %a'` で今を取る。**0 時〜4 時台は、前の日の続きとして扱う**（「今日」は前の日。締めるなら `--date <前の日>`）。
2. **雛形のままか。** `grep -c 'member-work:template' ./README.md` が 1 以上なら、「最初のセットアップがまだです。先にセットアップをします」と伝えて `/setup` に進む（daily はしない）。
3. **本人がはっきり言ったら、そのとおりに動く**（下の 4 の判断より先）:

| 本人の言い方 | 動き |
|---|---|
| 「出勤です」「始めます」「今日の予定は」 | 始業（今日の daily が既にあれば、予定の足し直しと取り込みだけ） |
| 「退勤です」「締めて」「終わります」「今日はここまで」 | 締め |
| 「取り込んで」「メールを見て」「チャットを見て」 | 取り込みだけ |
| 「こういう作業をやった」 | 日中 |
| 「md を直した」「表を直した」 | 本人が md を直したとき |

4. **はっきり言っていないとき**（「おはよう」「daily」「今日の分」など）は、上から順に見て決める:
   1. `./scripts/work-lint --unclosed` が「締めていない日」を出した → **先に「締め忘れの締め」を自分で行う**（本人に聞かない）。終わったら 2 へ進む。
   2. 今日の daily が無い → **始業**。
   3. 今日の daily が締めてある（`git ls-files` に今日の daily があり、`git status --short -- <今日の daily>` が空）→ 取り込みだけを回し、「今日はもう締めてあります。足すものがあれば言ってください。もう一度締めます」と伝える。
   4. 18 時以降で、今日の `work` が 1 行以上 → **締め**。
   5. 16 時〜18 時で、今日の `work` が 1 行以上 → 「今日はもう締めますか。まだなら、取り込みと記録の更新だけします」と一言だけ聞き、返事で締めか「日中」にする。
   6. それ以外 → **日中**（取り込みを回し、今日の記録の中身を見せる）。
5. 動いたあとは、どの場合も「8. 動いたあとの確認」を行う。

## 1. 締め忘れの締め（前の日より前。本人に聞かずに締める）

`./scripts/work-lint --unclosed` に出た「締めていない日」を、古い日からまとめて締める。

1. その日の daily を読む。`work` の空の `hours` は **`hours: unknown`** にする（推測で数字を入れない）。どの行を `unknown` にしたかを控える。
2. その日の `candidates` はそのまま残す（次の始業で出る）。タスクの状態は変えない。
3. 締めていない日を全部直したら、`./scripts/work-render --check` → `./scripts/work-render` → 日ごとに `./scripts/work-lint --close --date <その日>`。エラーは直す。直せないものは、その日の締めをやめて確認で伝える。
4. `git add -A` → `git commit -m "daily: <その日>（締め忘れ）"`（いくつもの日なら `daily: <日>・<日>（締め忘れ）`）→ `git push`（1 つずつ、別のコマンドで。失敗したときは「7. 締め」の 9 と同じ）。
5. 確認で「〇月〇日の締めがまだだったので、締めました。時間が分からない〇件を『不明』にしました（どの作業か）。分かれば教えてください。直して、今日の締めで送ります」と伝える。言われたら、その日の daily の `hours` を直す。
- 「GitHub に送っていない commit」だけが出たときは、ここでは何もしない（今日の締めで一緒に送られる）。確認で「前回 GitHub に送れなかった記録があります。今日の締めで一緒に送ります」と伝える。
- 「送り先（upstream）が決まっていない」と出たら、気にせず先へ進む。

## 2. 始業

1. **`git pull --ff-only` を流す。** 結果で分ける（エラーは原文で見る）:
   - `Already up to date.`・取り込めた → 先へ進む。
   - `There is no tracking information`（送り先が決まっていない）→ 黙って先へ進む。
   - `Not possible to fast-forward`・`diverging`・`would be overwritten`（GitHub とこの Mac の記録が分かれた・手元の変更とぶつかる）→ **ここで止める。** 次の文面で伝え、始業の残りはしない（このまま進めると、締めで GitHub に送れないため）:
     「GitHub にある記録と、この Mac の記録が分かれてしまい、最新を取り込めませんでした。このまま記録を続けると、締めで GitHub に送れなくなります。下のエラーをそのままエンジニアに送ってください。」（続けてエラーの原文をコードブロックで見せる）
   - それ以外（`Could not resolve host`・`Authentication failed`・`Permission denied`・`Operation not permitted` など、つながらない）→ 確認で「GitHub につながらず、最新を取れませんでした（エラーの原文）。今日の記録は続けられます」と伝えて先へ進む。
2. **取り込み**（下の「3. 取り込み」）。カレンダーは「今日の予定」と「前回より後に終わった会議の記録」の両方を頼む。
3. 読む:
   - `./tasks.yaml`（終わっていないもの。期日が過ぎたもの・今日・7 日以内のものを先に）
   - `./reminders.yaml` のうち、今日か 7 日以内に当たるもの（`date`、または `repeat` が今日に当たるもの）
   - `./scripts/work-lint --stale` が出す、長く動いていないタスク（`todo`・`waiting` のまま 30 日以上）。多ければ日数の長いものから 3 件まで
   - いちばん新しい前日以前の daily の `candidates`（返事待ちの候補）と、`plan` にあって `work` に無いもの
   - 候補からは、`tasks.yaml` に同じ内容があるものと、直近 14 日の daily の `rejected` に入っているものを外す（同じ候補を何度も出さない）
4. **今日の daily を作る**（既にあれば Edit で足すだけ）: `date`・`work: []`・`plan`（今日の予定の会議・期日が今日のタスク・前の日の `plan` で終わっていないもの）・`candidates`（前の日の返事待ち＋取り込みのタスクの候補。3 件まで）・取り込みの `filed` と `intake`。
5. `./scripts/work-render --check` → `./scripts/work-render`。commit はしない（締めでまとめて行う）。
6. 確認（「8.」）。始業では最後に「今日やることで、予定に無いものはありますか」と聞く。返事を受けて:
   - 今日やること → `plan` に足す。
   - 「はい」の候補 → `tasks.yaml` に足す（`status: todo`・`added: 今日`。期日を言われたら `due`）。`candidates` からは消す。
   - 「違う」の候補 → 今日の daily の `rejected` に移す。
   - 返事の無い候補 → `candidates` に残す（次にもう一度出す）。
   - 長く動いていないタスクに「続けます」→ `updated: 今日`。「やめます」→ `status: dropped`・`dropped: 今日`・`updated: 今日`、`note` に理由（本人の言ったまま。理由を言っていなければ「理由は？」と 1 回だけ聞く）。返事が無ければ何もしない（勝手に dropped にしない。次の始業でもう一度出る）。

## 3. 取り込み（始業・日中・締めで使う。「取り込みだけ」でも単独で回せる）

Google カレンダー・Gmail・Google Chat・Google ドライブを、**前回の取り込みより後の分だけ**見て、プロジェクトへ振り分けて格納する。経路ごとに調べ役のエージェント（`intake-collector`）を並べて回し、**生のメール・チャットはこの会話に読み込まない。**

1. **期間を決める。** 始め: `grep -h '^intake:' ./daily/*/*/*.yaml | sort | tail -n 1` の時刻（`intake:` が 1 つも無ければ、前の日の 0:00）。14 日より前なら 14 日前の 0:00 にし、「それより前は `/import` で取り込めます」と確認で添える。終わり: 今の時刻。
2. **アカウントを決める。** `CLAUDE.md` の「私のこと」にある Google のアカウント（MCP のサーバー名。無ければ `google-workspace`）。
3. **つながっているか。** そのサーバーのツール（`mcp__<サーバー名>__`）があるかをツールの検索で見る。無い・認証が切れていると分かったら、取り込みはせずに（`intake` も書かずに）先へ進み、確認で「Google につながっていないので、メール・チャット・予定は見ていません。つなぐときは『Google につないで』と言ってください（`google-workspace-connect`）」と伝える。
4. **集める。** `_inbox/intake/<YYYY-MM-DD-HHMM>/`（今の時刻）を置き場にして、`intake-collector` を **1 つのメッセージで、経路ごとに並べて**呼ぶ（`calendar`・`mail`・`chat`・`drive`。アカウントが複数なら、アカウント × 経路）。それぞれに、経路・期間・アカウント・置き場・使い方（`daily`）を渡す。カレンダーには、始業なら「今日の予定（一覧だけ）と、期間の中に終わった会議の記録」、それ以外は「期間の中に終わった会議の記録」と頼む。
5. **一覧を読む。** 返事と `_inbox/intake/<…>/<経路>.md`（一覧の表）を読む。1 件のファイルの原文は、決めるのに要るときだけ頭の数行を読む。
6. **振り分けて格納する（本人に 1 件ずつ聞かない。拙くても入れる）:**
   - プロジェクト: 一覧の見立て・`projects.yaml`・dev-tools の `project-catalog` の粒度で決める。同じスレッド・同じ相手は同じプロジェクトに揃える。
   - やりとり・会議: `mkdir -p ./projects/<slug>/_history/<YYYY>/<MM>` → `mv -n <置き場のファイル> ./projects/<slug>/_history/<YYYY>/<MM>/<DD>_<経路>_<件名>.md`（カレンダーの会議は経路 `meeting`）。`- 相手:` の行を `people.yaml` の `id` に Edit で直す（いない人は `people.yaml` に足す）。
   - 資料（一覧の「資料」）: そのプロジェクトの `resources/<今月>.yaml` に `title`・`url`・`kind`・`added: 今日`・`note`（概要 1 行）で足す。同じ URL が既にあれば足さない（`grep -rl --exclude='.env*' '<URL>' ./projects`）。
   - タスクの候補（一覧の「タスクの候補」・会議の宿題）: 今日の daily の `candidates` に（`tasks.yaml` にあるもの・直近 14 日の `rejected` にあるものは外す）。**タスクにはしない。**
   - 分かったこと（状態・次の一手・期日）: プロジェクトの `README.md` の「状態」「次の一手」を Edit で直す。
   - 決まらないもの・新しいプロジェクトが要りそうなもの: 置き場（`_inbox/intake/<…>/`）に残す。新しいプロジェクトは作らずに、確認で「〇〇というプロジェクトを作って入れますか」と聞く。
7. **自分でレビューする。** `./scripts/work-lint` を流し、`_history` の名前・相手・`resources` の形のエラーを直す。取り違え（同じスレッドが別のプロジェクトに入った）・重複（同じ `元:` が 2 つ）が無いかを、入れたファイルの `元:` の行で確かめる（`grep -rh --exclude='.env*' '^- 元:' ./projects | sort | uniq -d` が空）。
8. **残す。** 今日の daily の `filed` に、入れたものをプロジェクトごとに 1 行ずつ（例: `"web-aichi-maria: メール 2 件・会議 1 件（10/21 定例。宿題 2 件は候補に）"`・`"resources: web-aichi-maria に 1 件（移管の見積もり表）"`・`"people.yaml: 愛知マリアクリニックの佐藤さんを足した"`）。`intake:` を今回の終わりの時刻に上書きする。
9. `./scripts/work-render --check` → `./scripts/work-render` → `./scripts/work-lint`。
- 予定の一覧（始業の「今日の予定」）は、始業の `plan` と確認に使う（ファイルにはしない）。
- 取り込みだけのとき（「取り込んで」）は、ここまでで確認（「8.」）へ。あとで定期実行から回すときも、この 3. だけを回せばよい。

## 4. 日中（「こういう作業をやった」）

- 今日の daily の `work` に 1 行足す（`project`・`task`・`hours`）。時間を言っていなければ聞かずに `hours:` を空にしておき、締めでまとめて聞く。
- メール・チャットの文面や相談の中身を渡されたら、`RULES.md` の「受け取ったもの・作ったものの置き場」どおりに `_history` などへ置き、`work` の行の `links` に足す。初めての相手は `people.yaml` に足す。
- 計画・調べもの・下書きを一緒に作ったら、そのプロジェクトの `plan/`・`research/`・`draft/` に置き、プロジェクトの `README.md` の「中にあるもの」に 1 行足す（`RULES.md` の「プロジェクトの中で自分で作るもの」）。
- 本人が「タスクにして」と言ったものは、その場で `tasks.yaml` に足す。「終わった」と言われたタスクは、その場で `status: done`・`done: 今日` にする。「やめた」「もういらない」「〇〇にまとめた」と言われたタスクは `status: dropped`・`dropped: 今日` にし、`note` に理由を書く（移すのはどちらも締めで）。状態を変えたら `updated: 今日`。
- 既にある YAML は Edit で直す（Write で書き直さない）。
- 書いたら `./scripts/work-render --check` → `./scripts/work-render` → `./scripts/work-lint`（`--close` は付けない。空の `hours` は注意が出るだけ）。
- 「はっきり言っていない」呼び出しで日中になったときは、取り込み（「3.」）を回してから確認（「8.」）。

## 5. 本人が md を直したとき（「md を直した」「表を直した」、または `--check` が「手で直された」を出したとき）

生成物の md（`tasks.md`・`reminders.md`・`daily/.../<日付>.md`）は、本人が見やすい所で直すことがある。上書きせずに YAML へ戻す。

1. `./scripts/work-render --check` で「手で直された」md を出す。
2. `./scripts/work-render --diff <その md>` を流す。`-` の行が YAML から作った形、`+` の行が今の md。本人が変えた中身（状態・期日・内容・時間など）を、表の列と見比べて読み取る（commit 済みの md の直しも、まだ commit していない md の直しも、同じく読める）。
3. 対応する YAML を Edit で直す:
   - `tasks.md` の「やること」→ `tasks.yaml`、「終わったもの」→ その行の終わった月の `tasks/<YYYY-MM>.yaml`（まだ移していないものは `tasks.yaml`）
   - `reminders.md` → `reminders.yaml`
   - daily の md → 同じ日付の YAML
4. もう一度 `./scripts/work-render --diff <その md>` を流し、残った差分が YAML に書けない部分（見た目だけの直しなど）だけになったことを確かめる。
5. 「md の〇〇を YAML に反映しました（何をどう変えたか 1 行ずつ）」と伝える。YAML に書けない直しは「md を作り直すと消えます」と添える。読み取れない変更は、推測で入れずに聞く。
6. `./scripts/work-render --force <その md>` で、その md だけを YAML から作り直す（`--force` は 1 ファイルずつ。ここで YAML に戻し終えた md にだけ付ける）。

## 6. 本人に「違う」と言われたとき（取り込み・会話の反映の直し）

「それは違う」「こっちのプロジェクト」「その人は〇〇さん」と言われたら、そのとおりに自分で直す。聞き返さない。

- 別のプロジェクトへ: `mv -n` で `_history` のファイルを移し、`resources` の行も移す（今月のファイルどうし）。README の「状態」も直す。
- 人の取り違え: `people.yaml` と `- 相手:` の行を直す。
- 直したら render → lint を流し、今日の daily の `filed` に「直した: …」を 1 行足し、本人には「〇〇を△△に直しました」と 1 行で伝える。

## 7. 締め（「締めて」「退勤です」、または判断で締めになったとき）

締める日は今日（0 時〜4 時台なら前の日。以下「締める日」）。

1. **md の手直しを拾う。** `./scripts/work-render --check` で「手で直された」md があれば、上の「5.」を先に行う。
2. **取り込み**（「3.」）。カレンダーは「期間の中に終わった会議の記録」を頼む。
3. **作業の実績とタスクの候補を、1 つのメッセージで聞く:**
   - 締める日の daily の `work` を一覧で見せ、「これで合っていますか。時間の空いているものは何時間ですか（分からなければ『分からない』で大丈夫です）」。
   - 今日の会話・`work`・`_history`・取り込みから、まだ `tasks.yaml` に無い「やること」に見えるもの（`candidates` を含む）を **3 件まで**（直近 14 日の `rejected` にあるものは選ばない）:「これはタスクではありませんか（番号で答えてください。違うものは『違う』と）」。
4. 返事を入れる: 時間は本人の申告のまま（足し算や丸めはしない。「分からない」は `hours: unknown`）。「はい」の候補 → `tasks.yaml` に足す。「違う」→ `rejected` へ。返事の無い候補 → `candidates` に残す（次の始業でもう一度出す）。
5. 終わったと言われたタスクを `status: done`・`done: 締める日`（やめたものは `status: dropped`・`dropped: 締める日`・理由の `note`）にし、`./scripts/work-render --move-done` で `tasks/<YYYY-MM>.yaml` へ移す（手で切り貼りしない）。
6. `./scripts/work-render --check` → `./scripts/work-render` → `./scripts/work-lint --close`（締める日が今日でなければ `--close --date <その日>`）。
   - エラーは直す。直せないものは本人に一言で伝え、commit の前に止める。
   - 前の日の daily の空の `hours` は注意として出るだけ。本人に「〇月〇日の〇〇の時間は分かりますか」と 1 回だけ聞き、言われたら数字か `unknown` を入れる。分からないままでも締めは進める。
7. `git status --short` で変わったファイルを見て、思わぬもの（`RULES.md` の置き場に無いファイルなど）が無いか確かめる。あれば本人に聞く（`_inbox/` の取り込みの残りは、そのまま commit してよい）。
8. `git add -A` → `git commit -m "daily: <締める日>"` → `git push`（1 つずつ、別のコマンドで）。
   - commit が `nothing to commit`（変わったものが無い）と言ったら、そのまま push へ進む（前に送れなかった commit があれば、ここで一緒に送られる）。
9. **push に失敗したら、別のやり方で送り直そうとしない。** 次の文面で伝え、エラーの原文をコードブロックでそのまま見せる:
   「GitHub に送れませんでした。今日の記録はこの Mac には残っています。下のエラーをそのままエンジニアに送ってください（次の始業でも、送れていない記録としてお知らせします）。」
10. 確認（「8.」）。締めでは「今日の合計時間（md の「やったこと」の見出しの数字。不明・未記入の件数も）・足したタスクの数・明日に持ち越すもの」を入れる。抜けや食い違いを言われたら直し、もう一度 6〜8 を流す（commit の題は同じ）。

## 8. 動いたあとの確認（どの場合も、最後に 1 回）

何をしたかと、記録の中身を短く見せて、本人に確かめてもらう。**15 行まで。** 番号を振り、返事を番号で受けられるようにする。

```
【したこと】
- 10/20 の締めがまだだったので締めました（時間が分からない 2 件を「不明」に: 見積もりの下書き・社長と電話）
- 今日の記録を始めました
- 取り込み: メール 5 件・チャット 3 件・会議 1 件を、3 つのプロジェクトに入れました（10/20 18:00〜10/21 09:10 の分）
【今日の記録】
- 予定: 10:00 定例（愛知マリアクリニック）・見積もりを送る（期日 今日）
- やったこと: まだなし
- 会話・取り込みから入れたもの: web-aichi-maria に会議のメモ／people.yaml に佐藤さん
- 入れられなかったもの: 2 件（_inbox/intake/2026-10-21-0910/）。「〇〇」というプロジェクトを作って入れますか
【返事がほしいもの】
1. これはタスクではありませんか: 移管の見積もりを作る（10/24 まで）
2. 〇月〇日の「社長と電話」は何時間でしたか
3. 「名刺を作る」は 40 日動いていません。やめますか・続けますか（やめるなら理由も一言）
抜けや食い違いがあれば教えてください。
```

- 「会話・取り込みから入れたもの」は、今日の daily の `filed` から（記録係が会話から反映したものも含む）。前に見せたものは、まとめて「ほか 〇件」でよい。
- 推測で埋めたもの（`unknown` にした時間・振り分けに迷って入れたもの）は、必ず「したこと」に書く。
- 返事で直すもの: 時間・候補（「はい」「違う」）・振り分けの違い（「6.」）・新しいプロジェクト（「はい」なら `/work-rules` の手順で台帳と README を作り、置き場に残したものを入れる）。

## やらないこと

- git の操作は、始業の 2-1（pull）、締め忘れの締めの 1-4 と締めの 7-8（add・commit・push）と、`./scripts/work-lint --unclosed` の中の読み取りだけ。`reset`・`checkout`・`restore`・`switch`・`rebase`・`merge`・`branch`・`stash` はしない。
- メール・チャットを送らない・下書きを作らない。予定・Google のファイルを作らない・変えない。
- 時間を推測で埋めない（分からなければ `unknown`）。合計や集計を自分で計算して YAML に書かない（md の合計は `work-render` が出す）。
- 候補を 4 件以上並べない。`rejected` にあるものは出さない。取り込み・会話から見つけたものを、本人の「はい」無しにタスクにしない。
- 新しいプロジェクトを、本人に聞かずに作らない（人は足してよい）。
- `./scripts/work-render --force` は、手で直された md を YAML に戻し終えたとき以外に使わない。付けるときは md を 1 つ指定する。
