# 最初の取り込み（import）

過去のやりとりと ChatGPT のメモから、プロジェクトの整理を作って、原文を入れる。**一度で完璧にしない。** 取り込んだあとは、本人が Claude と一緒に、daily の中で少しずつ育てていく。

置き場・YAML の形は `RULES.md`（とくに「取り込み」「`_history` のファイルの中身」）、書く手順は `/work-rules`。日付は `date +%F` で取る。

- **送信は絶対にしない。** Gmail・Google Chat・ChatGPT の画面の操作は、読み取りだけ。
- **生のメール・チャットを、この会話に読み込まない。** 集めるのは調べ役のエージェント（`intake-collector`。Sonnet）。この会話で読むのは、エージェントの返事と一覧の表だけ。

## 0. どこまで進んだかを見る

進み具合は `_inbox/import/README.md` に書く（無ければ作る）。呼ばれるたびに読み、済んでいない段から進める。

```markdown
# 取り込みの進み具合

- 期間: 2026-07-01 〜 2026-10-21
- [x] ① 材料（1 回目: 本人がやりとりに入っているもの）… _inbox/intake/import-2026-10-21-1000/
- [ ] ① 材料（2 回目: 本人が入る前のやりとり）
- [ ] ① 材料（ChatGPT）… _inbox/chatgpt/
- [ ] ② 整理案 … _inbox/import/整理案.md
- [ ] ③ 本人が直した
- [ ] ④ 反映（projects.yaml・README・people.yaml）
- [ ] ⑤ 原文（_history・resources）
```

本人に「前回は〇〇まで済んでいます。続きから進めます」と一言伝えてから始める。

## ① 材料を集める

### Gmail・Google Chat

1. Google Workspace の MCP のツールがあるかを、ツールの検索で見る。無い・認証が切れていれば、dev-tools の `google-workspace-connect` スキルを案内する（つながるまで、ChatGPT の材料だけで進めてよい）。
2. 期間を決める。本人に 1 回だけ「どのくらい前から取り込みますか（目安: 今の仕事を担当し始めたころ。決まらなければ 3 か月前から）」と聞く。決まったら `_inbox/import/README.md` に書く。
3. **1 回目（本人がやりとりに入っているもの）**: `intake-collector` を、**期間を 1 か月ずつに切り、経路（`mail`・`chat`）ごとに**、1 つのメッセージで並べて呼ぶ（例: 3 か月なら 3 × 2 ＝ 6 つ）。使い方は `import`、置き場は `_inbox/intake/import-<YYYY-MM-DD-HHMM>/`（今回の分で 1 つ）、探す条件は「本人がやりとりに入っているもの（送った・返した・宛先や CC に入っている・本人が入っているスペースで本人が発言したスレッド）」。一斉配信・自動の通知・宣伝は外す。
4. **2 回目（本人が今かかわっている案件で、本人が入る前のやりとり）**: 1 回目の一覧から、案件ごとに相手のドメイン・人・件名の言葉を拾い、案件ごとに 1 つずつ `intake-collector` を並べて呼ぶ（探す条件にそれを渡す。期間は、本人が入る前の数か月。CC で本人に来ている社内向けのやりとりも含める）。例: 愛知マリアクリニックを 8 月から担当していれば、7 月以前の、別の社員とクライアントのやりとりを、クライアントのドメインと件名の言葉で探す。
5. 重複は、各ファイルの `元:` の ID で調べ役が除く（同じ ID は置かない）。エージェントが「200 件で止めた」と返したら、続きの期間でもう一度呼ぶ。

### ChatGPT

- 本人が貼ったメモリーの文面・会話の書き出しを、`_inbox/chatgpt/<YYYY-MM-DD>_<名前>.md` にそのまま置く（会社のワークスペースでは公式のエクスポートが使えないので、本人が貼ったものか、Claude in Chrome で画面から読み取ったものが来る）。
- Claude in Chrome で読み取るときは、本人が開いた画面を読むだけ（入力・送信・設定の変更をしない）。
- メモリーの中身は、②の整理案（仕事・人）と、`CLAUDE.md` の「私の好み」の案に使う。会話のうち仕事のものは、⑤で `_history` に経路 `claude`（AI との会話）で入れる。

## ② 整理案を出す

1. dev-tools の `project-catalog` スキル（プロジェクトの粒度・区分・slug の案）を読む。
2. 一覧の表（`_inbox/intake/import-…/<経路>.md`）と ChatGPT の材料を棚卸しして、`_inbox/import/整理案.md` を書く:

```markdown
# 整理案（直してください）

## プロジェクト

| slug | 名前 | 状態 | やりとりの件数 | 代表的な件名 | メモ |
|---|---|---|---|---|---|
| web-aichi-maria | 愛知マリアクリニック | active | 42 | サイトの移管・ページの制作 | 8 月から担当。7 月以前は別の社員 |

## 人

| id | 名前 | 呼び方 | 所属 | 役割 | メモ |
|---|---|---|---|---|---|

## どこにも入らないもの

- 〇件（例: 社内の一斉のお知らせ）。入れないでよければ、そのままにします
```

3. 本人に、件数の多い順に 5 行ほどの要約と、ファイルの場所を見せる:「この案で分けるのがよいと思います。`_inbox/import/整理案.md` を直すか、ここで『これはまとめて』『これは分けて』『名前はこう』と言ってください」。**勝手に作らない。**

## ③ 本人が直す

- 本人が md を直したら読み直す。チャットで言われたら、そのとおりに `整理案.md` を直して見せ直す。「これでいい」と言われるまで繰り返す（1 回で終わらなくてよい）。
- 決まったら `_inbox/import/README.md` の ③ に印を付ける。

## ④ 反映する

- 決まった整理で、`/work-rules` の手順どおりに作る: `projects.yaml` に 1 件ずつ（`started` は最初のやりとりの日）・`projects/<slug>/README.md`（材料から分かる状態・関係する人・次の一手）・`people.yaml`。
- ChatGPT のメモリーから分かった好みは、`CLAUDE.md` の「私の好み」の案として本人に見せ、「はい」の分だけ足す。
- `./scripts/work-render --check` → `./scripts/work-render` → `./scripts/work-lint`。

## ⑤ 原文を入れる

1. 一覧の表の行ごとに、決まったプロジェクトへ `mv -n` で移す: `./projects/<slug>/_history/<YYYY>/<MM>/<DD>_<経路>_<件名>.md`（月のディレクトリは `mkdir -p`）。`- 相手:` の行を `people.yaml` の `id` に Edit で直す。数が多いので、プロジェクトごと・月ごとにまとめて `mv -n` する。
2. 添付は、要るものだけ本人に Downloads に保存してもらい、`_files/<YYYY-MM-DD>_<名前>.<拡張子>` に移す（移す前に名前を見せる）。
3. 共有された Google のドキュメントなどの URL は、`resources/<今月>.yaml` に概要（`note`）と一緒に入れる（登録した月のファイル。過去の月のファイルは作らない）。
4. どこにも入らないものは、`_inbox/intake/import-…/` に残す。
5. `./scripts/work-render --check` → `./scripts/work-render` → `./scripts/work-lint`。取り違え・重複（`grep -rh --exclude='.env*' '^- 元:' ./projects | sort | uniq -d` が空）を確かめる。
6. 本人に 5 行以内で: 作ったプロジェクト〇件・人〇人・入れたやりとり〇件（プロジェクトごと）・残したもの〇件。「ここから先は、毎日の daily の中で少しずつ育てていきます。違うところは『それは違う』と言ってください」と添える。
- commit・push は、次の daily の締めでまとめて行う（ここではしない）。

## やらないこと

- メール・チャットを送らない。Gmail・Google Chat・ChatGPT の画面で、入力・送信・設定の変更をしない。
- 本人が「これでいい」と言う前に、プロジェクト・人を作らない。
- タスクを作らない（タスクの候補は、次の daily の始業で聞く。一覧の「タスクの候補」は今日の daily の `candidates` に 3 件まで）。
- 過去の月の `resources`・`daily` を作らない（`_history` は、やりとりのあった月のディレクトリに入れる）。
- git の操作はしない。
