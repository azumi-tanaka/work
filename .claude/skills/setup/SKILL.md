# 最初のセットアップ（雛形 → 本人の repo）

雛形のままの work repo を、本人（例: 田中さん）の repo にする。**聞く前に、まず探す。** 探して分かったことを案として見せ、本人に直してもらう（一から質問攻めにしない）。

置き場・YAML の形は `RULES.md`（書く手順は `/work-rules`）。日付は `date +%F` で取る。メール・チャットは送らない。

## 0. どこまで済んでいるかを見る（呼ばれるたびに）

- `grep -c 'member-work:template' ./README.md` が 0 なら、セットアップは済んでいる。「セットアップは済んでいます」と伝えて終わる（本人が直したいところを言ったら、`CLAUDE.md` などをその場で直す）。
- 1 以上なら雛形のまま。下の 1〜6 のうち、済んでいないところから進める。済んでいるかは、次で見る:

| 段 | 済んでいる印 |
|---|---|
| 1. 探す | `_inbox/setup/探索.md` がある |
| 2. 本人に確かめる・CLAUDE.md | `CLAUDE.md` の「私のこと」の `- 名前:` が空でない |
| 3. 人と仕事 | `people.yaml` か `projects.yaml` が空（`[]`）でない |
| 4. Google の接続 | `_inbox/setup/探索.md` に「接続の確認:」の行がある |
| 5. README | `README.md` に印が無い（ここで印が消える。だから最後に近い段にする） |
| 6. commit・push | `git status --short` が空 |

- 本人に「前回は〇〇まで済んでいます。続きから進めます」と一言伝えてから始める。

## 1. 探す（聞く前に）

1. Google Workspace の MCP（`mcp__google-workspace__`）のツールがあるかを、ツールの検索で見る。
   - **ある** → 2 へ。
   - **無い・認証が切れている** → 「Google につなぐと、メールや予定から最初の案を作れます。いまつなぎますか（あとでも大丈夫です）」と聞く。「つなぐ」なら dev-tools の `google-workspace-connect` スキルを回してから 2 へ。「あとで」なら探さずに 3 へ（聞き取りだけで進める）。
2. 調べ役のエージェント `intake-collector` を、**1 つのメッセージで経路ごとに並べて**呼ぶ（`calendar`・`mail`・`chat`・`drive`）。使い方は `setup`、期間は直近 30 日、アカウントは `google-workspace`。返ってくるのはまとめだけ（生のメールはこの会話に入れない）。
3. まとめを `_inbox/setup/探索.md` に書く（よくやりとりする相手・今動いていそうな仕事・定例の会議・よく使う資料・本人の名前と所属の手がかり）。探していないときは「探索なし（聞き取りだけ）」と書く。

## 2. 本人に確かめる → CLAUDE.md

1. 探して分かったことから、**案を 1 つのメッセージで**見せる（番号を振る。分からないところは空けて「教えてください」）:
   - 名前・呼び方（Claude が本人を何と呼ぶか）・所属・役割
   - よくやりとりする相手（10 人まで。社内・社外）
   - 今動いている仕事（3〜6 件。dev-tools の `project-catalog` の粒度で。名前と slug の案）
   - 見る Google のアカウント（ふつうは本人の 1 つ。共有のアカウントもあれば）
   - 好み（話し方・呼ばれ方・「この相手のメールはこう扱う」など。無ければ空でよい）
   「違うところ・足りないところを教えてください。ほぼ合っていれば『それで』で大丈夫です」と添える。
2. 返事を受けて、`CLAUDE.md` を Edit で直す:
   - 1 行目を `# <名前>さんのプライベートナレッジスペース` に、3 行目を「<名前>さんの仕事の記録と整理の置き場。Claude と一緒に使う。」にする。
   - 「私のこと」の名前・呼び方・所属・役割を埋める。Google のアカウントは MCP のサーバー名で書く（メールアドレスは書かない）。共有のアカウントがあれば、`  - google-workspace-<名前>（〇〇の共有のアカウント）` の形で 1 行ずつ足す（そのサーバーが dev-tools で入っていなければ、「エンジニアに『Google の共有のアカウントを足してほしい』と伝えてください」と言う）。
   - 「私の好み」に、聞いた好みを 1 行ずつ。
   - 「この repo の決まり」の節は変えない（雛形の更新を取り込むときにぶつからないように）。

## 3. 人と仕事（最初の数件だけ）

- `people.yaml` に、本人と、よくやりとりする相手（確かめた分だけ）を足す（`id`・`name` と、分かる `call`・`org`・`role`・`contact`）。本人の `id` は名字のローマ字など。
- 今動いている仕事を、`/work-rules` の「プロジェクトを決める」の手順で作る（`projects.yaml` に 1 件ずつ・`projects/<slug>/README.md`。README には分かっている状態・関係する人・次の一手を書く）。**最初は 3〜6 件まで。** 全部を先に作らない（あとで `/import` や daily の中で足す）。

## 4. Google の接続を確かめる

- dev-tools の `google-workspace-connect` スキルを回し、サービスごとに使えるかを本人に表で見せる。つながらないものがあっても、先へ進む（「エンジニアに伝えてください」とエラーの原文を見せる）。
- 結果を `_inbox/setup/探索.md` の最後に「接続の確認: <日付> Gmail ✅・Chat ❌ …」と 1 行書く。つながず進めたときは「接続の確認: <日付> つないでいない」。

## 5. README を本人向けに書き換える（雛形の印が消える）

`README.md` を、下の形で**丸ごと書き直す**（Write。雛形のエンジニア向けの説明は、本人の repo には残さない。雛形の repo の側には残っている）。`<名前>` は本人の名前。

```markdown
# <名前>さんのプライベートナレッジスペース

<名前>さんの仕事の記録と整理の置き場です。Claude（Claude Desktop の Code タブ）と一緒に使います。ここに書いたものは、<名前>さんの GitHub の private な repo に保存されます。

## 毎日の使い方

- 何と送っても大丈夫です（「おはよう」「daily」「今日の分」など）。Claude が時刻と記録を見て、1 日の始め・取り込み・終わりの締めを決めて動きます。はっきりさせたいときは「出勤です」「退勤です」と送ってください。
- 朝: 今日の予定・期日の近いタスク・メールやチャットから見つけた「タスクではありませんか」を出します。
- 日中: 「〇〇をやった」「このメールを入れておいて」「〇〇の段取りを一緒に考えて」と送ると、記録や資料が残ります。
- 夕方: 「締めて」で、やったことと時間を確かめて、GitHub に保存します。
- Claude が動いたあとは、何をしたかを短く見せます。違っていたら「それは違う」「こっちのプロジェクト」と言えば直します。

## どこに何があるか

- `projects/` … 仕事（プロジェクト）ごとの置き場。開くと、いまの状態と、計画・調べもの・下書き・やりとり・資料が見られます
- `tasks.md` … やること ／ `reminders.md` … 期日・定期の用事 ／ `daily/` … 毎日の記録
- `CLAUDE.md` … Claude への「私のこと」「私の好み」（自由に書き足してください）

## 困ったとき

- 「GitHub に送れませんでした」などのエラーが出たら、そのエラーをエンジニアに送ってください。
- 決まり（`RULES.md`）や仕組み（`scripts/`・`.claude/`）を変えたいときは、エンジニアに相談してください。
```

## 6. 確かめて、保存する

1. `./scripts/work-render --check` → `./scripts/work-render` → `./scripts/work-lint`。エラーは直す。
2. `git status --short` で変わったファイルを見せる（`CLAUDE.md`・`README.md`・`people.yaml`・`projects.yaml`・`projects/…`・`_inbox/setup/…`）。
3. `git add -A` → `git commit -m "setup: <名前>さんの repo にする"` → `git push`（1 つずつ、別のコマンドで）。push に失敗したら、エラーの原文を見せて「エンジニアに送ってください」と伝える（別のやり方で送り直さない）。
4. 最後に 5 行以内で: 作ったもの（プロジェクト〇件・人〇人）・Google の接続の結果・次にやること（「明日の朝から『おはよう』と送ってください」「過去のメールやチャット、ChatGPT のメモをまとめて取り込むときは『取り込みをしたい』と言ってください（`/import`）」）。

## やらないこと

- メール・チャットを送らない。Google の予定・ファイルを作らない・変えない。
- `RULES.md`・`scripts/`・`.claude/` を変えない。`CLAUDE.md` の「この repo の決まり」の節は変えない。
- プロジェクトを一度に全部作らない（最初は 3〜6 件）。
- git の操作は 6 の add・commit・push だけ。
