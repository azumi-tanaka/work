# work repo に書くときの手順

**置き場・ファイル名・月での分け方・YAML の形の正は `RULES.md`**（`./scripts/work-lint` はそれで検査する）。書く前に、`RULES.md` の該当する節を読む。ここには、書く順番だけを置く。

## プロジェクトを決める

1. `projects.yaml`（台帳）を読み、当てはまるプロジェクトに入れる。終わったもの（`status: done`）に入れたくなったら、本人に「終わった〇〇に入れますか」と聞く。
2. 迷ったら本人に「〇〇（`slug`）に入れますか」と 1 回だけ聞く。
3. 新しく作るときは、名前（日本語）を本人に確かめ、slug を決める（粒度と区分は dev-tools の `project-catalog` スキルを目安にする。区分を頭に付けるなら、台帳にある区分に揃える）。台帳に 1 件足し（`status: active`・`started: 今日`）、`projects/<slug>/README.md` を作る（1 行目は `# <日本語の名前>`）。
4. 「この件は終わった」と言われたら、台帳の `status: done`・`ended: 今日` にする。ディレクトリは動かさない。

## 置き場を決める

まず「それは何か」で 4 つに分ける（混ぜない）。詳しくは `RULES.md` の「受け取ったもの・作ったものの置き場」。

| それは | 置き場 |
|---|---|
| 相手とのやりとりの原文・会議の記録 | `projects/<slug>/_history/<YYYY>/<MM>/` |
| 受け取った実物（PDF・画像など） | `projects/<slug>/_files/`（必要なら `resources` に `path` で索引を足す） |
| 外部の資料（Google のドキュメントなど）の URL | `projects/<slug>/resources/<今月>.yaml`（概要の `note` を付ける） |
| 自分で作るもの（計画・実行プラン・叩き台・調べもの・まとめ） | `projects/<slug>/plan/`・`research/`・`draft/`（下の「自分で作るものを置く」） |

## 自分で作るものを置く（計画・調べもの・下書き）

`RULES.md` の「プロジェクトの中で自分で作るもの」。浅い所ほど抽象・よく見るもの、深い所ほど具体・たまにしか見ないもの。

1. 用途を決める: これからやること（計画・段取り）は `plan/`、分かったこと（調べもの・比較・まとめ）は `research/`、人に出すものの下書きは `draft/`。
2. 1 つの話は 1 ファイル（`<名前>.md`）。日付は付けない（その日の版として残すものだけ `<YYYY-MM-DD>_<名前>.md`）。名前に空白は使わない。
3. 同じ話が育って何ファイルにもなったら、話のディレクトリ（`<名前>/`）を作り、入口の `README.md`（要約と中のファイルへのリンク）を置いて、細かいものをその中へ。深さは用途のディレクトリの下に 2 段まで。
4. **足したら、1 つ上の入口から辿れるようにする。** 用途のディレクトリの直下に足したら、プロジェクトの `README.md` の「中にあるもの」に、リンクと 1 行の説明を足す。話のディレクトリの中に足したら、その `README.md` に足す（`./scripts/work-lint` が辿れないものを注意で出す）。
5. プロジェクトの `README.md` の「状態」「次の一手」も、そのとき分かったことに直す。

## 書く

1. 置き場と名前を `RULES.md` の「受け取ったもの・作ったものの置き場」「名前の決まり」で決める。日付は `date +%F` で取る。
2. 相手がいるものは、`people.yaml` にその人がいるか見る。いなければ先に足す（`id`・`name` と、分かる項目だけ）。
3. ディレクトリが無ければ作る（月のディレクトリ `_history/<YYYY>/<MM>/` も）。
4. YAML は `RULES.md` の形のとおりに書く（インデントは半角スペース 2 つ。`: ` を含む文字列や `[`・`#` で始まる文字列は、値全体を `"..."` で囲む）。
5. **既にあるファイルを変えるときは Edit で直す。** Write で丸ごと書き直すと、直すつもりの無い部分（本人や前の Claude が書いた行・コメント）まで消したり変えたりしてしまうため。Write を使うのは、新しく作るファイルだけ。
6. YAML を変えたら、**先に `./scripts/work-render --check` を流す。** 「手で直された」と出た md があれば、render の前に `/daily` の「本人が md を直したとき」で YAML に戻す。そのあと `./scripts/work-render` を流す（md は生成物）。
7. 書き終わったら `./scripts/work-lint` を流し、エラーが出たら直す（日中は `hours` の空欄は注意だけ。`--close` は締めのときだけ付ける）。直せないものは本人に一言で伝える。

## 迷ったとき

- `RULES.md` に無い置き場・キーが要りそうなら、足さずに本人に「決まりに無いので、エンジニアに伝えてください（何を置きたいか）」と伝える。それまでは `_inbox/` に置く。
- やってはいけないこと（月をまたいだ追記・md の手直し・原文の書き換え・ファイルの削除・機微な値・送信・git の操作）は `RULES.md` の「git」「やってはいけないこと」。
- `scripts/` を書き換えたくなったら、`RULES.md` の「scripts を書き換えるとき」（先に本人に確かめ、エンジニアに相談してもらう）。
